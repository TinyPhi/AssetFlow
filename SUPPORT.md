# Getting Support for AssetFlow

Thank you for using AssetFlow! This document explains the channels available for getting help, asking questions, reporting bugs, and obtaining commercial support.

---

## 1. Community Support

AssetFlow is open-source software maintained by its core contributors and community. Community support is provided on a best-effort basis through public channels:

- **Documentation**: Always check our comprehensive documentation in [`docs/`](docs/) first. Common topics, architecture decisions, and configuration guides are covered there.
- **GitHub Discussions**: For questions about architecture, best practices, deployment options, or general usage advice, join our [GitHub Discussions](https://github.com/bikash-barnwal/AssetFlow/discussions).
- **GitHub Issues**: If you have found a reproducible bug or wish to propose a feature that adheres to our design principles, please open an issue using the appropriate template in [GitHub Issues](https://github.com/bikash-barnwal/AssetFlow/issues).

---

## 2. Bug Reports and Feature Requests

Before filing a new issue:
1. Search existing open and closed issues and discussions to see if the topic has already been addressed.
2. Verify that the problem reproduces on the latest `main` or supported release.
3. Review [`CONTRIBUTING.md`](CONTRIBUTING.md) for contribution guidelines and expectations.

Please provide complete reproduction steps, environment details (OS, Docker/Podman version, database version), and sanitized logs.

---

## 3. Security Vulnerabilities

**Do not report security vulnerabilities through public GitHub issues or discussions.**

If you believe you have discovered a vulnerability or security flaw in AssetFlow, please follow the coordinated disclosure process described in [`SECURITY.md`](SECURITY.md) and email **security@tinyphi.com**.

---

## 4. Commercial Support and Enterprise Licensing

For organizations requiring guaranteed response times, deployment assistance, custom domain templates, SLA-backed support, or alternative commercial licensing exemptions (dual-licensing for non-AGPL proprietary deployments):

- **Commercial Licensing**: Email `licensing@tinyphi.com`
- **Enterprise Services & Support**: Email `support@tinyphi.com`
